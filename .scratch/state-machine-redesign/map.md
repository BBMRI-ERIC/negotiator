# State machine redesign

## Destination

A complete design spec (decisions + ADRs) for a replacement lifecycle state-machine subsystem, covering: (a) the engine — replacing Spring Statemachine with a hand-rolled FSM or a genuinely fitting adopted library, chosen from a clean slate; (b) a persistence model for Resource-lifecycle state-machine *definitions* as configurable data (states/events/transitions/guards/info-requirements), associable with a Resource directly or via its Network(s); the Negotiation-level lifecycle keeps one definition (also externalized from hardcoded Java, not per-network); (c) information requirements as a first-class part of the definition model for both the Negotiation and Resource lifecycles (today they only gate Resource transitions); (d) architectural improvements that fall out along the way (e.g. resolving the enum/config drift seen in the current implementation). REST API/vocabulary compatibility is preferred but not a hard constraint. This map ends in a spec ready to hand off — implementation happens in separate follow-on efforts, not in this map.

Networks live in `eu.bbmri_eric.negotiator.governance.network` (`Network` is many-to-many with `Resource`; `Negotiation` has no direct network link).
- **Reference docs**: `docs/lifecycle.md`, `docs/administrator.md` (information-requirements admin section).

## Decisions so far

- [Definition model](issues/01-definition-model.md) — one unified `StateMachineDefinition`/`State`/`Event`/`Transition` schema (relational, not a blob) for both lifecycles; guards/actions via a named Java registry keyed from transition rows; a distinct `required_authority` field (`NONE`/`IS_ADMIN`/`IS_CREATOR`/`IS_REPRESENTATIVE`); info requirements attach at the Event level; drops `NegotiationState.APPROVED`, `NegotiationEvent.START`, `RETURN_FOR_RESUBMISSION` event/state as truly dead, but keeps `OVERRIDE` as a transition-less audit tag (soft requirement — refactor away if the engine choice makes it awkward). *Wiring-shape amendment (resolves the ordering review finding): two separate wiring tables — guard wiring is one table with a nullable `transition_id` carrying ticket 07's machine/transition scopes (partial unique indexes per scope), action wiring is transition-only; both realized as a `WebhookEventMapper`-style strategy-bean registry with string type-keys and per-strategy typed `params` (jsonb); actions keep `params`; cross-scope order is engine pipeline logic, not an `order` column.*
- [Engine landscape research](issues/02-engine-landscape-research.md) — no viable off-the-shelf FSM library (Spring Statemachine EOL, all but a few named alternatives dormant — `jd-easyflow`, `davidmoten/state-machine`, and `pnavais/state-machine` are the active exceptions); workflow engines are too heavy or licensing-encumbered (Flowable is the cleanest OSS option but full BPMN weight; Camunda 8 core requires a paid license); hand-rolled data-driven estimate ~2,500–4,000 LOC (1.5–2.5× current 1,493 LOC). No recommendation made — feeds the Engine choice ticket.
- [Engine choice](issues/03-engine-choice.md) — hand-rolled, not adopted (no library fits the bespoke schema/registry without bending it, and it'd only cover the cheap part anyway); one shared stateless-evaluator engine core for both lifecycles, definition graph cached per `(definition_id, version)`; Spring Statemachine deleted entirely (dependency + all ~25 classes); `OVERRIDE` kept as a transition-less `Event` row. Info-requirement/engine integration and the possible-events API contract explicitly deferred to the Information requirements ticket.
- [Information requirements as first-class model](issues/05-info-requirements-model.md) — 0..N unordered requirements per `Event`, each with a configurable assignee (representative / `Person` / lightweight `Group` reference, satisfaction = any qualifying submission from the audience); satisfaction is a real `GuardType` (structured `GuardResult`, not a bare boolean) in one shared `evaluate()` pipeline used for both the real gate and the possible-events dry run; **no new API endpoint/DTO** — `getPossibleEvents` keeps today's shape, simply omitting blocked events; existing `requirement-{id}`/`submission-{id}` hint links carry over with an inclusion-condition fix (structural reachability, not "lifecycle link exists"), a display fix (show the blocking event's label), and a HAL cleanup to array-valued `requirement`/`submission` rels; `InformationSubmission` gains `submittedBy`; extends to the Negotiation lifecycle via `Event`'s scope-agnostic shape. Bulk-fetch batching for a known `ResourceWithStatusAssembler` N+1 flagged as follow-on, not designed here.
- [Event-requirement guard-chain wiring mechanism](issues/07-event-requirement-guard-wiring.md) — implicit: the engine always evaluates the firing Event's Requirements as a built-in pipeline stage (no wiring rows, structurally impossible to omit — not a registry-wireable GuardType after all, amending ticket 05's wording); definition-level guards added as a second first-class wiring scope (`NEGOTIATION_APPROVED` becomes one definition-level entry, amending ticket 01's transition-only wiring); evaluation order `required_authority` → requirements check → guard rows (definition-level then transition), short-circuiting, ordered by expected failure likelihood with monotonic failure categories (403 → 422 → 409).
- [Resource-Network association & conflict/versioning](issues/04-resource-network-association.md) — definitions form versioned **families** (immutable `family_key` distinct from the editable `name` label, one active row per family); direct Resource association always wins over Network resolution; Network association is optional with a global default family as fallback; multi-Network conflicts (differing families for a shared Resource) are rejected at write-time via an application-level `NetworkService` check, exempting Resources with a direct override; versioning is pin-at-start — `NegotiationResourceLink`/`Negotiation` record the resolved version via an immutable `definition_version_id` FK, so in-flight work never moves to a newer version. *Governance/cost amendment (resolves the two ticket-04 review findings): the global default is an admin-only `is_global_default` flag on the family (versions like any other, default-ness is resolution-time only); the multi-Network conflict check is exhaustive but a single set-based query per write, acceptable because rare — a Network-priority alternative was reconsidered and rejected as silent ambiguity.*
- [Definition version/identity reconciliation](issues/08-version-identity-reconciliation.md) — the row id is a definition version's sole machine identity (all FKs, including the pin); `version` survives as a per-family, system-assigned incrementing display sequence (unique on `(family_key, version)`, assigned at row creation, gaps harmless); ticket 03's engine cache is re-keyed to the version row's id alone. Amends tickets 01, 03, and 04, resolving the review's cross-ticket incoherence findings.
- [Lifecycle coupling: fan-out / fan-in](issues/09-lifecycle-coupling.md) — coupling is an orchestration layer over the stateless engine, on the existing ticket 01/07 schema with **no new coupling table or persisted parent→child instance rows**. **One self-firing primitive**: *an orchestration trigger attempts a definition's automatic events from the current state; the guard pipeline decides* — two sources (child-transition-commit, fully specified; clock tick, declared and deferred). "Automatic" is a new **`SYSTEM`** `required_authority` value (amends ticket 07), not a `NONE` overload — a `SYSTEM` event fails authority for every human caller, so it's orchestrator-only. **FEEDBACK** = implicit, zero-config post-commit re-attempt of the parent's `SYSTEM` events (no coupling rows); `CONCLUDE` = `SYSTEM` + a parameterized **`TERMINAL_AGGREGATION`** guard (`ALL`/`ANY`/`N_OF_M`, config today `ALL`) that asks each resource's own pinned definition if its state is terminal. **SPAWN** = a wired-once `SPAWN_RESOURCE_LIFECYCLES` action on the sole Negotiation definition's approval transition (resource defs carry no spawn config); per resource it **resolves** (ticket 04) → **pins** the version FK (ticket 08) → **initializes** to the definition's initial state, atomically, pin-at-approval against the final resource set. Adds **`initial` + `terminal` flags to `State`** (amends ticket 01). Double-fire safety = source-state check for correctness + parent row-lock for no duplicate work. Clock-scheduler plumbing deferred (rides ticket 10's parked reminders/expiry); outcome-sensitive conclusion and late-added resources ruled out/flagged (see Out of scope + the ticket's Deferrals).
- [Audit/history model redesign](issues/06-audit-history-model.md) — minimal change: each `LifecycleRecord`'s `@Enumerated` `changedTo` enum column becomes a `state_id` FK to a `State` row, timeline label rendered live by join (`state.getLabel()`). Labels are **not** frozen — a label edit may ripple into historical text, accepted as identical to today's enum-rename behavior (so no snapshot, option b dropped). **No version column** on the audit tables: version is implied transitively via `State.definition_id` and recovered by join (resolves the redundancy finding); versioning mechanics not re-opened. Firing `Event`, from-state, and audit-table unification all deliberately deferred (additive later); `OVERRIDE` records its resulting state like any other row. Was the last blocker on the migration fog item.
- [Migration / rollout path](issues/11-migration-rollout-path.md) — a single forward-only **convert-in-place** Flyway cutover (Flyway 11 Community has no `undo`; rollback = pre-deploy snapshot restore, no retained legacy columns, no dual-write). Live `current_state` stays an authoritative VARCHAR resolved via the `(pinned version, name)` natural key — **no `current_state_id` FK** (clarifies ticket 06's FK conversion is audit-only), just gaining the pin and losing its now-obsolete CHECK. Two v1 families seeded via **raw frozen SQL** (Resource family = `is_global_default`); every negotiation/link pins to v1 (drafts included). **Dead states `APPROVED`/`RETURNED_FOR_RESUBMISSION` survive as transition-less audit-only `State` rows** (amends ticket 01: "dropped" = out of the active graph, not physically absent — mirrors `OVERRIDE`) so history/live strings resolve and ticket 06's `state_id` FK lands; dropped *events* stay fully omitted. IRs re-home by name (`for_event`→`event_id`), defaulting audience=`RESOURCE_REPRESENTATIVES`, quantifier=`ANY`, `submittedBy`=`NULL` (never recorded; rare one-off resubmit accepted). Audit `changed_to`→`state_id` by same-name join to the one v1 version (no version column, ticket 06). **Stop-the-world cutover** (migration is breaking for old code that reads `for_event`), short maintenance window, in-flight work safe (state in DB, additive changes). Packaging: additive-DDL migration, then one atomic data-cutover file ordered assert→seed→backfill→NOT NULL→drop, all id refs via name/family-key subqueries.
- [Information-requirement audience, aggregation & contact](issues/10-info-requirement-audience-contact.md) — designs the IR model *around* ticket 05's boolean seam with **no persisted per-IR-occurrence instance**. **Audience** = a resolver registry mirroring ticket 01's strategy beans (`audience_type`+`audience_params` on `Requirement`), one primitive `resolve(params, context) → Set<PersonRef>`; three strategies `RESOURCE_REPRESENTATIVES` (RESOURCE-only) / `NEGOTIATION_CREATORS` / `IAM_GROUP(groupKey)` (both), scope-compatibility declared and write-time-validated. **Quantifier** = `distinct qualifying members ≥ threshold` (`ANY`=1, `N_OF_M`=N, `ALL`=live `|audience|`), counted by distinct member, qualifying iff `submittedBy ∈ audience`; **live re-resolution, no snapshot** (drift harmless — the guard only gates the firing instant; the committed state is a persisted fact never re-derived). **Contact** = a **built-in post-commit structural stage** `NOTIFY_IR_AUDIENCE` keyed on the target state's one-hop requirement-bearing events (not admin-wired — can't-forget, paired with ticket 07's built-in check; amends the rationale doc's action-registry framing), notifying only currently-unsatisfied members with no contact record (self-suppressing re-entry). **Derive-don't-store** confirmed end-to-end; invariant locked: a state is derivable iff its entering action leaves a domain fact (`submit`→row; `contact` leaves none, safe only because it's a side effect not a state), gating the parked `waive`/reminder/multiple-outcome upgrades. Amends ticket 05 (assignee → audience resolver).

## Out of scope

- **IAM / LS-AAI group membership-sync mechanics** — how the `IAM_GROUP` audience resolver (whose *interface* is designed in [Information-requirement audience, aggregation & contact](issues/10-info-requirement-audience-contact.md) — `resolve(params, context) → Set<PersonRef>` with `groupKey` params) actually fetches/mirrors LS-AAI virtual groups: membership resolution, sync/caching, refresh cadence. Implementation plumbing the definition spec depends on but does not need to specify; the resolver interface is settled here and this map has consistently framed the sync mechanics as a separate follow-on effort. Ruled out of scope 2026-08-10 to keep the destination on the state-machine definition model — returns as its own effort if picked up.
- **Outcome-sensitive conclusion** — differentiated conclusion (e.g. all-delivered vs all-unavailable routing to distinct terminal outcomes; the "child terminal state → parent event" map). A lifecycle/product change beyond this redesign, whose baseline is today's single outcome-blind `CONCLUDED`. Ruled out by [Lifecycle coupling: fan-out / fan-in](issues/09-lifecycle-coupling.md), which showed the `SYSTEM`-event + `TERMINAL_AGGREGATION`-guard mechanism **accommodates it as later config** (extra mutually-exclusive `SYSTEM` events from `IN_PROGRESS`) — so it's excluded, not foreclosed.
